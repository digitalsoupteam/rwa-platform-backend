# Каталог паттернов

## Назначение

Помочь ревьюеру быстро находить нарушения и пропущенные паттерны при code review.
Вместо того чтобы держать все соглашения в голове, ревьюер открывает нужный файл
и сверяет код с эталоном.

## Как устроен каталог

Каждый файл описывает один паттерн или антипаттерн — с примерами правильного
и неправильного подхода. Файлы логически разделены:

| Файл | О чём |
|------|-------|
| `ARCHITECTURAL_PATTERNS.md` | Архитектурные решения: структура сервиса, DI, плагины, сквозные кросс-сервисные соглашения |
| `CODING_PATTERNS.md` | Кодовые паттерны: именование, типизация, трассировка, обработка ошибок, логирование |
| `REVIEW_CHECKLIST.md` | Чеклист ревью: что проверять в каждом PR в первую очередь |

## Существующие файлы

- [`services/example/examples.service.ts.md`](services/example/examples.service.ts.md) —
  эталонный референс сервиса (687 строк, 13 секций). Выжимка из 20 живых сервисов:
  структура, соглашения, обязательные паттерны с пояснениями.

## Что дальше

Файлы `ARCHITECTURAL_PATTERNS.md`, `CODING_PATTERNS.md` и `REVIEW_CHECKLIST.md`
пока не созданы — они появятся по мере анализа и формализации паттернов.
Как только файл появится, он будет добавлен в таблицу выше.
